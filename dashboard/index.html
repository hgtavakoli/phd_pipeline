⚙ Advanced renderer settings (ray casting / sampling — affect dataset quality)

spp is the main quality/speed knob: 8 = fast iteration (denoiser cleans the noise), 32–64 = final dataset quality. More bounces = better indirect light, slower. Full reference: Docs → Hyperparameters.

Output: SmartSDG\Datasets\yolo_experiments\ — every run ends with a FINAL DATASET SUMMARY in the console.

Pipeline Self-Test

11 checks across configs, assets, class-ID registry, converter quality filters, exp routing — plus a real generation, training and AL loop in full mode. Run after every change.

② Object Detection Training

Fine-tune a YOLOv12 detector on a generated dataset, driven by its AAS config. Each camera geometry trains as its own run.

Record mode: empty fields use the values stored in the selected AAS file; filled fields are saved into the dataset's AAS file (under AAS\datasets\) so it always documents your latest training parameters. Pipeline templates at the AAS root (v0.x, v2.0) are never modified — overrides there apply to the run only. Each selected camera trains as its own run — untick one to train on a single camera. Per-dataset AAS configs are created automatically after every generation (in AAS\datasets\<date>\). Tip: batch 32 may exceed the RTX 2080's 8 GB at img 640 with YOLOv12-L — use 8–16, or pass -1 for auto-fit.

③ Inference — view mode:

Run inference on a folder of images

Pick a trained model and a folder of images. The detector runs on each image and displays predicted bounding boxes with class labels — useful for sanity-checking a model or reviewing how it performs on a new image set.

Live inference — webcam, IP camera, or video

Stream annotated detections in real time from a local webcam, a network IP camera (RTSP/HTTP), or a video file. The dashboard server opens the source and streams annotated frames to the browser.

Webcam: opened by the dashboard server (this machine). IP camera: paste the full RTSP or HTTP URL (e.g. rtsp://admin:pass@192.168.1.10:554/stream). Video: plays through once with boxes drawn. Stop releases the source.

① Harvest real-image candidates

Run a trained detector over a folder of real, unlabelled images. The most uncertain frames (where the model is least confident) are kept with predicted boxes as pre-labels — the best images to label next, feeding the AL experiment below.

② Review candidates

Predicted boxes shown. Accept → moves image + verified labels into a REAL_<name> dataset (trainable/AL-able). Reject → discards it. Use ✏ Edit to correct boxes before accepting.

③ Active Learning experiment

Train a model on a small labelled subset, then let it pick the most useful images to label next, round by round — reaching high accuracy with fewer labels. Pick a generated dataset as the pool and compare strategies on the same data.

Record mode: your choices are saved into the dataset's AAS. Validation runs on the real image set (sim-to-real). Each camera geometry runs and is logged separately so the two never mix.

Gain overview — mAP50 vs labelled images

Each line is one AL run (dataset + camera + strategy). Run the same dataset/camera with different strategies to see which reaches higher accuracy for the same number of labelled images.

⑤ Continual Learning — add new classes without forgetting

Teach an existing model a new object class while keeping what it already knows (class-incremental). Uses replay of old-class images mixed into each batch to prevent catastrophic forgetting.

If the new-class data isn't in the pool yet, the dashboard offers to generate it first (SDG) and then run CL. The model's class list is extended and written back to the dataset's AAS (record mode).

CL overview & comparison

Each CL run with its final accuracy and cost. Compare a CL step against full retraining (Results tab) to weigh accuracy vs time/resources.

📜 Pipeline Log — factory-wide event history

Every action across the whole pipeline (generation, training, AL, CL, inference, harvest) is appended to the AAS PipelineHistory submodel — the modular, trackable factory record other modules can consume. Stored at AAS\pipeline_history.json.

⚙ Execution — run heavy stages in Docker

Training, Active Learning and Continual Learning can run inside a GPU Docker container instead of the local conda env (SDG/Isaac, harvest and live always run natively). Opt-in, per machine.

spp is the main quality/speed knob: 8 = fast iteration (denoiser cleans the noise), 32–64 = final dataset quality. More bounces = better indirect light, slower. Full reference: Docs → Hyperparameters.

Object Detection Training

Record mode: empty fields use the values stored in the selected AAS file; filled fields are saved into the dataset's AAS file (under AAS\datasets\) so it always documents your latest training parameters. Pipeline templates at the AAS root (v0.x, v2.0) are never modified — overrides there apply to the run only. Each selected camera trains as its own run — untick one to train on a single camera. Per-dataset AAS configs are created automatically after every generation (in AAS\datasets\<date>\). Tip: batch 32 may exceed the RTX 2080's 8 GB at img 640 with YOLOv12-L — use 8–16, or pass -1 for auto-fit.

Active Learning (PPAL)

Record mode: the chosen strategy and budget are saved into the dataset's AAS file. The selected dataset becomes the unlabeled pool; validation runs on the real image set (sim-to-real). Per-round learning curve is written to active_learning\output\<dataset>\al_summary.csv — run once per strategy on the same dataset + seed for the ablation comparison.

Harvest AL candidates from real images (inference-time)

Run a trained model over a folder of real, unlabeled images. The most uncertain frames (where the model is least sure) are kept with the model's predictions as pre-labels — these are the most valuable real images to label next.

Review candidates

Predicted boxes shown. Accept → moves the image + verified labels into a REAL_<name> dataset (then trainable like any dataset). Reject → discards it. Refine boxes in any YOLO labeller — files are standard format.
